# Custom Control Reference

Besides the UI5 library controls, a view can use the controls the abap2UI5
frontend ships itself: a camera, a file upload, the device position, a
WebSocket, the Excel bridge, a dirty flag. Each is a UI5 control under the
module namespace `z2ui5.cc`, so a view declares the namespace once and
writes the control like any other:

```abap
DATA(view) = z2ui5_cl_ui5_view_builder=>factory(
    )->ele( n = `View` ns = `mvc`
        )->a( n = `xmlns`       v = `sap.m`
        )->a( n = `xmlns:mvc`   v = `sap.ui.core.mvc`
        )->a( n = `xmlns:z2ui5` v = `z2ui5.cc`

        )->tag( n = `Geolocation` ns = `z2ui5`
            )->a( n = `latitude`  v = client->_bind( latitude )
            )->a( n = `longitude` v = client->_bind( longitude )
            )->a( n = `finished`  v = client->_event( `POSITION` )
        )->stringify( ).
```

A property is bound like a property of any control, an event is wired to
the backend with `client->_event( )`, and the event's parameters arrive as
described on the [Backend Events](/cookbook/event_navigation/backend) page. What a
control does and when to use it is on the cookbook page its section links;
this page **is** the contract those pages explain against, generated from
the control's own metadata on the framework's `main` branch by
`npm run generate:controls` and held fresh by `check:controls`. Edit the
intro, never the block.

How to write a control of your own, and ship it with an app, is on
[Custom Controls](/advanced/extensibility/custom_control) under
Extensibility.
