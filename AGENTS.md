# AGENTS.md — abap2UI5 documentation site

This repository is the abap2UI5 documentation site: a VitePress ^1.6 project
published to https://abap2ui5.github.io/docs/ via GitHub Pages
(`.github/workflows/deploy.yml`). All content lives under `docs/`.

## Commands

```sh
npm ci               # install
npm run docs:dev     # local dev server with hot reload
npm run docs:build   # production build (also generates llms-full.txt and sitemap.xml)
npm run docs:preview # serve the production build locally
```

## Audience policy — important

**The site content is written for human readers.** AI-facing guidance lives in
the framework repository (`abap2UI5/abap2UI5`: `AGENTS.md`, `llms.txt`,
`docs/agents/building-apps.md`). Do not add AI-oriented pages, agent briefings
or prompt material to this site — that was done once and deliberately removed
(PR #132).

Machine *delivery formats* are a different thing and must be kept working.
They make the human-facing content readable for machines without changing the
site in any visible way:

- `docs/public/llms.txt` — hand-maintained link index at
  https://abap2ui5.github.io/docs/llms.txt. Update its links when pages are
  added, moved or removed.
- `llms-full.txt` — generated at build time by the `buildEnd` hook in
  `docs/.vitepress/config.mjs`: all guide pages (every sidebar section except
  "Resource") concatenated as plain markdown in navigation order. Never edit
  by hand; it regenerates on every build.
- `sitemap.xml` — generated by VitePress (`sitemap` option in `config.mjs`).

## Conventions

- **Every new page needs a `sidebar` entry** in `docs/.vitepress/config.mjs`,
  otherwise it is unreachable (and missing from `llms-full.txt`).
- Frontmatter: `outline: [2, 4]` on every page; `####` for sub-sections.
- ABAP samples are **complete, runnable classes** (full `DEFINITION` +
  `IMPLEMENTATION`), not fragments with ellipses. Use backtick string
  literals in ABAP code.
- Use VitePress containers (`::: tip`, `::: warning`, `::: details`,
  `::: code-group`) as the existing pages do.
- The version badge in the nav is **derived from the top entry of
  `docs/resources/changelog.md`** at build time — to bump the version, add
  the release notes entry; never hard-code a version in `config.mjs`.
- Internal links are root-relative (`/cookbook/...`); VitePress applies the
  `/docs/` base automatically.

## Transition phase — view builder (do not "fix" this)

The docs currently teach `z2ui5_cl_xml_view` as the fluent view helper. The
framework plans to replace it with `z2ui5_cl_ai_xml`, but that migration is a
**deliberate, pending maintainer decision — do not migrate the docs (or add
banners announcing the change) until the maintainer asks for it**. Until then,
`z2ui5_cl_xml_view` is the correct class to document.
